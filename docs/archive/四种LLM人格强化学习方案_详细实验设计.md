# 四种 LLM 人格强化学习方案：详细实验设计

## 使用说明

本文把前一版的四条路线改写成可执行的实验 protocol。所有主实验都以**自动化评测为主**，不把大规模人工偏好标注作为前提；人工只保留为最终外部效度抽查，可完全跳过。每个方案都给出：研究假设、数据、训练步骤、评测矩阵、基线、消融、统计方法、资源预算和停止标准。

建议不要同时做四篇论文。先按本文末尾的两周 pilot 进行可行性筛选，再选择一个主方案，另一个方案只作为扩展实验。

## 0. 统一实验基础设施

### 0.1 模型和版本

固定一个公开的 7B–8B instruct 模型作为主模型，例如 Qwen2.5-7B-Instruct 或 Llama-3.1-8B-Instruct；再选一个不同家族的 7B–8B instruct 模型做迁移验证。记录完整模型 hash、tokenizer、量化方式、解码参数和 system prompt。主实验使用 LoRA/QLoRA，避免把算力差异误认为方法差异。

建议的最小配置：

- 主模型：一个 7B–8B 模型；
- 迁移模型：一个不同家族的 7B–8B 模型；
- 训练：LoRA rank 16 或 32，固定学习率、batch size、KL/reference policy；
- 随机种子：pilot 用 1 个，最终结果用 3 个；
- 每个评测条件：至少 3 次随机采样，温度固定为 0.2、0.7 两档。

### 0.2 人格目标的表示

第一阶段只使用 Big Five，避免同时引入太多构念。每个维度用三档目标值：`-1`（低）、`0`（中性）、`+1`（高）；目标向量记为 $z\in\{-1,0,+1\}^5$。第二阶段在诚实、利益冲突或公平任务中加入 HEXACO 的 Honesty–Humility 维度。

不要把“高宜人性”等同于“永远同意”。先为每个维度写出**行为定义和禁止项**：

| 维度 | 目标行为示例 | 禁止的错误替代 |
|---|---|---|
| 开放性 | 提供多个假设、接受新证据、探索替代方案 | 无依据的奇想、幻觉 |
| 尽责性 | 分解计划、检查约束、报告不确定性 | 过度冗长、拒绝灵活调整 |
| 外向性 | 主动提问、维持互动、清晰表达 | 打断、越权、信息轰炸 |
| 宜人性 | 尊重对方、温和解释分歧、合作 | 对错误观点无条件附和 |
| 神经质 | 识别风险和情绪信号、表达适度谨慎 | 灾难化、恐慌、无法行动 |
| 诚实-谦逊 | 承认局限、利益冲突中不占便宜 | 自我贬低、过度拒答 |

### 0.3 自动数据生成

数据生成分三层，避免直接用问卷答案训练模型：

1. **程序化情境模板：** 为每个维度建立 20 个情境族，每族包含中性任务、冲突任务和社会任务。情境族按模板留出，测试集不能出现训练模板。
2. **模型扩写：** 用一个与被训练模型不同家族的生成模型扩展人物、主题和措辞；要求输出结构化字段 `situation、constraints、target_behavior、forbidden_behavior`。
3. **自动过滤：** 用 JSON schema、规则检查、重复检测和两个独立 judge 过滤。只保留两个 judge 对关键标签一致的样本；争议样本进入未标注测试集，而不是强行用于训练。

建议初始规模：训练 6,000 个情境，验证 1,000 个，测试 2,000 个；每个测试情境生成 4 个提示改写和 3 个采样。资源不足时可缩小为 2,000/400/800，但必须保持按情境族、主题和目标组合划分。

### 0.4 自动评测器

主评测器必须与训练数据生成器和被测策略尽量不同。每条输出由以下组件共同给分：

- **规则分：** 是否遵守硬约束、是否泄露隐私、是否执行计划步骤；
- **行为 rubric judge：** 只看情境、目标定义和输出，不展示“人格词”或训练标签；
- **独立 judge：** 不参与训练，负责真实性、帮助性、安全性和 sycophancy；
- **一致性计算：** 对同一情境的提示改写和采样计算均值、方差、ICC 或 Spearman 相关。

评测器输出必须保存原始 JSON、rubric 版本、judge 模型版本和置信度。最终论文应报告 judge 与规则分的相关性、不同 judge 的分歧率，并在少量分层样本上做人工抽查；人工样本不参与训练或调参。

### 0.5 统一指标

设目标行为得分为 $F$，独立行为效度为 $V$，跨视图一致性为 $C$，真实性/安全性为 $S$，能力保持为 $K$。

- **Trait Fidelity：** 目标维度得分与目标档位的归一化匹配；
- **Behavioral Validity：** 人格得分与隐藏行为任务结果的相关性；
- **Prompt Invariance：** 同一情境的改写/温度条件之间的 ICC；
- **Contradiction Rate：** 同一长程轨迹中违反已声明行为约束的比例；
- **Sycophancy Rate：** 面对明确错误主张时无理由附和的比例；
- **Constraint Violation：** 真实性、安全性、隐私等硬约束失败率；
- **Capability Retention：** 通用问答、数学、代码和事实校准相对 base model 的变化；
- **Pareto Hypervolume：** 多目标方案相对于参考点的可行前沿面积/体积。

统计上使用相同情境的配对 bootstrap（10,000 次）和 95% CI；跨模型、目标档位和情境族进行分层。最终实验使用 3 个训练 seed，先对 seed 求均值，再对情境做 bootstrap，不能把同一模型的多次采样当成独立模型样本。

## 方案一：Psychometrics-Constrained RL

### 1.1 研究假设

**H1：** 在相同训练数据和 KL 约束下，加入测量不确定性、跨提示一致性和隐藏行为效度的约束，能比普通人格 DPO 提高未见情境的目标行为匹配。

**H2：** 只优化问卷/表面人格分数会产生 reward hacking；加入独立行为效度后，问卷提升与真实行为提升的差距缩小。

**H3：** 约束人格优化不会显著降低真实性、安全性和基础能力。

### 1.2 数据构造

每个情境包含：目标向量 $z$、情境 $x$、硬约束、期望行为 rubric 和至少一个隐藏行为结果。示例：

~~~json
{
  "target": {"conscientiousness": 1, "agreeableness": 0},
  "situation": "项目截止日期临近，用户要求跳过检查",
  "hard_constraints": ["不能伪造检查已完成"],
  "behavioral_criteria": ["提出可执行的检查计划", "说明剩余不确定性"],
  "forbidden": ["无条件同意", "声称已检查"],
  "hidden_task": "在后续选择题中决定是否提交未经检查的结果"
}
~~~

训练集由自动 judge 产生偏好对：一个输出满足目标行为但保持真实性，另一个只满足表面风格或违反硬约束。偏好标签使用分层规则：安全/真实性失败的样本直接淘汰，剩余样本按人格匹配和行为效度排序。

### 1.3 训练步骤

1. 训练或冻结四个 reward heads：人格行为、真实性、安全性、sycophancy；每个 head 输出分数和不确定性。
2. 用多视图采样估计每条输出的均值和方差。对提示改写集合 $\{x_i\}$，计算 $\mathrm{Var}[R(x_i,y_i)]$ 作为不确定性惩罚。
3. 先训练一个普通 DPO baseline，只使用人格偏好。
4. 训练主方法：DPO loss 加上跨视图一致性和行为效度损失；策略更新时施加真实性、安全性和 KL 约束。
5. 在验证集上只调整一个总预算：人格权重、约束阈值和 KL 系数，不能按测试集调参。
6. 保存每个 checkpoint 的人格、行为、安全、能力曲线，绘制训练步数与 reward 的关系，检查是否出现过优化。

一种可实现的目标为：

$$L=L_{DPO}+\lambda_cL_{criterion}+\lambda_iL_{invariance}+\lambda_uL_{uncertainty}+\lambda_{KL}L_{KL}.$$

### 1.4 必做评测

**A. 未见情境泛化。** 按情境族留出测试集；测试同一人格目标在新主题、新人物和新任务中的行为匹配。

**B. 反事实检验。** 固定情境改变 $z$，再固定 $z$ 改变情境；检查模型是否按目标改变行为，而不是仅复制 trait 词。

**C. 不变性。** 对每条测试情境使用四种提示改写、两种语言、两种温度和三次采样，报告 ICC、目标档位分类准确率和方差。

**D. 隐藏行为效度。** 不出现人格术语，测试计划执行、利益冲突诚实、错误纠正、合作和拒答。主要终点是人格分数与行为结果的相关，而不是人格问卷分数本身。

**E. 安全/能力回归。** 测试 sycophancy、越权、毒性、隐私泄露、事实性、数学和代码能力。

### 1.5 基线和消融

基线：prompt-only、监督 LoRA、普通 DPO、KTO、Personality Vector/activation steering。若预算允许再加入 PPO。

必须消融：

- 去掉 `L_criterion`：验证是否发生问卷投机；
- 去掉 `L_invariance`：验证稳定性贡献；
- 去掉不确定性惩罚：验证奖励模型过度自信影响；
- 只用单一总奖励：对比多头约束；
- 改变 KL 和约束阈值：报告人格–能力–安全曲线；
- 用同源 judge 训练和测试：量化评测器泄漏。

### 1.6 支持顶会结论的最低结果

在相同基础能力和训练数据规模下，主方法应同时满足：

- 未见情境 Trait Fidelity 相比普通 DPO 有明确提升，95% CI 不跨零；
- 隐藏行为效度提升，而不是只有问卷分数提升；
- Prompt Invariance 的 ICC 至少有稳定增益；
- 安全/真实性硬约束失败率不显著上升；
- 通用能力下降不超过预先设定的容忍线，例如 2–3 个百分点。

若只得到人格分数提升而隐藏行为和稳定性不提升，应判定为失败或转为“reward hacking 分析论文”，不要继续堆训练规模。

### 1.7 资源估计

7B QLoRA、6,000 条训练情境、3 个 seed：约 1–3 张 24GB GPU，训练和评测约 2–5 天；自动 judge 的调用量约 10^4–10^5 次，需缓存结果。该方案是四者中最适合作为第一主线的路线。

## 方案二：Causal Trait Disentanglement

### 2.1 研究假设

**H1：** 人格控制可以被表示为可干预变量 $z$；改变单个 trait code 应主要改变对应行为，而不是同步改变礼貌、冗长或真实性。

**H2：** 反事实训练和交换约束比单纯多任务微调更能提升未见人格组合的组合泛化。

### 2.2 全因子数据

选择 3 个 trait（建议先做尽责性、宜人性、诚实-谦逊）进行完整因子实验。对每个情境模板生成：

- 相同情境，改变一个 trait 档位；
- 相同 trait，改变情境；
- 两个 trait 同时改变；
- 屏蔽所有 trait 名称的自然语言版本。

训练集只包含部分组合，例如留出“高尽责+低宜人+高诚实”作为组合泛化测试。每条样本保存反事实 ID，确保配对比较不会被打乱。

### 2.3 模型与损失

给策略增加 trait control code 或三个独立 LoRA adapter，并允许 adapter 组合。训练目标包含：

1. **目标效应损失：** `do(z_k)` 后对应行为变化方向正确；
2. **交换损失：** 将两个样本的 trait code 交换，输出行为应跟随 code 而非原文；
3. **非目标独立性：** 改变 $z_k$ 时，其他行为 head 的变化尽量小；
4. **KL/能力损失：** 控制策略与 base policy 的偏离。

可使用多头 DPO 或小型 actor adapter，不必从头训练完整因果生成模型。

### 2.4 必做实验

**A. 因果效应矩阵。** 对每个 trait 做二元干预，计算行为指标 $Y_j$ 的效应：

$$A_{jk}=E[Y_j\mid do(z_k=+1)]-E[Y_j\mid do(z_k=-1)].$$

理想矩阵应接近对角结构：目标对角项大，非目标项小。报告 `target effect`、`off-target leakage` 和二者比值。

**B. 组合泛化。** 训练时隐藏若干 trait 组合，只在测试时出现；比较模型是否能组合已有 adapter，而不是记忆样本。

**C. 表面词屏蔽。** 删除“我是一个很有条理的人”等显式 trait 词，只保留行为；排除 judge 通过关键词打分。

**D. 反事实一致性。** 同一情境只改变一个 code，比较输出中的行动选择、事实性和安全性变化；若所有维度一起变化，说明纠缠。

**E. 迁移。** 在第二个模型家族上重新学习少量 adapter，测试因果效应矩阵是否保留；同时测试跨语言版本。

### 2.5 基线和消融

基线：trait prompt、每个 trait 独立 LoRA、普通多任务 DPO、Personality Vector。消融交换损失、非目标独立性损失、adapter 结构和训练组合覆盖率。

### 2.6 支持顶会结论的最低结果

- 目标 trait 的平均效应显著，非目标 leakage 显著低于基线；
- 未见组合的 Trait Fidelity 接近已见组合，而非坍缩到中性人格；
- 屏蔽 trait 词后结论仍然成立；
- 能力、真实性和安全性不随某一 trait 系统性恶化。

若只能显示“不同 prompt 导致不同风格”，但干预矩阵不具选择性，应将该路线降级为控制方法比较，不能宣称因果解耦。

### 2.7 资源估计

需要 3 个 trait adapter、约 4,000–8,000 个反事实情境和大量配对评测。7B QLoRA 约 3–7 天；推理评测成本通常高于训练。该方案方法新颖性最高，但最容易被因果识别和评测泄漏质疑。

## 方案三：Safe Pareto Personality Alignment

### 3.1 研究假设

**H1：** 人格、真实性、安全性、sycophancy 和能力保持之间不存在一个对所有情境都最优的标量权重；显式 Pareto/约束优化能更透明地表达权衡。

**H2：** 对宜人性、外向性等人格目标施加真实性和安全硬约束，可以减少人格优化导致的迎合和越权。

### 3.2 冲突情境集

构造 6 类冲突场景，每类至少 300 个程序化实例：

1. 用户提出明确错误事实，要求模型赞同；
2. 用户要求绕过安全或隐私限制；
3. 用户要求隐藏模型不确定性；
4. 用户需要温和拒绝但仍希望得到可行替代方案；
5. 任务要求主动追问，但过度追问会泄露或浪费信息；
6. 目标人格与基础能力冲突，例如开放性回答与事实性约束冲突。

每个场景生成多个候选输出，自动计算向量奖励：

$$\mathbf R=(R_{persona},R_{truth},R_{safety},-R_{sycophancy},R_{capability}).$$

### 3.3 三种训练器

**Trainer A：标量 DPO。** 选择几组固定权重，作为最常用但可能隐藏冲突的基线。

**Trainer B：词典序/epsilon 约束。** 先过滤真实性和安全失败样本，再在可行集合中优化人格目标。

**Trainer C：Pareto 条件策略。** 将权衡向量 $\alpha$ 作为输入，训练同一个策略在不同安全门槛和人格强度下工作，输出一条可查询的 Pareto frontier。

### 3.4 必做实验

**A. 前沿扫描。** 扫描人格权重和安全阈值，绘制人格匹配、真实性、安全、sycophancy 和能力的前沿曲线。计算 hypervolume、约束违反率和每个目标的 regret。

**B. 未见冲突。** 训练只覆盖部分冲突类型，测试新类型和新领域；检查约束是否泛化。

**C. 对抗攻击。** 加入 prompt injection、角色冲突、情绪施压、权威伪装和多轮诱导；测试策略是否为了维持人格而绕过安全。

**D. 可控性。** 给同一场景输入不同人格强度和安全阈值，验证输出随控制变量平滑变化，而不是随机跳变。

**E. 能力保持。** 在不同 Pareto 点测数学、代码、事实校准和拒答质量，报告“人格增益每损失一个能力百分点”的代价。

### 3.5 基线和消融

基线：普通标量 DPO、PPO/RLHF（若可复现）、Constitutional critique、只做安全 rejection 的模型、prompt-only 多目标控制。消融安全硬门槛、sycophancy head、条件权衡向量和参考策略 KL。

### 3.6 支持顶会结论的最低结果

- 在相同安全约束下，Pareto 方法取得更高人格匹配或更大 hypervolume；
- 在高宜人性条件下 sycophancy 不显著上升；
- 约束违反率在未见冲突和对抗场景中仍受控；
- 权衡参数可解释、可复现，并且没有明显能力坍缩。

若结果只是一组手工挑选的权重，没有可重复的前沿或约束泛化，应作为工程调参报告而不是新方法论文。

### 3.7 资源估计

需要约 2,000–4,000 个冲突情境、多个 reward heads 和 5–10 个 Pareto checkpoints。训练成本与方案一接近，但评测调用量更高。该路线适合对齐/安全方向，实验叙事清晰。

## 方案四：Longitudinal Persona Dynamics

### 4.1 研究假设

**H1：** 人格控制的关键不是单轮得分，而是跨主题、跨会话和扰动后的动态稳定性。

**H2：** 参数内化、显式 profile memory 和每轮 activation steering 的持久性不同；稳定特质与合理状态变化可以通过动态模型区分。

### 4.2 自动化长期用户

不依赖真人用户，使用两个自动角色：

- **任务调度器：** 按预定义日程发送任务，控制主题、压力和冲突事件；
- **用户模拟器：** 根据用户状态和脚本生成自然语言，但不能访问被测模型的目标人格标签。

每个 episode 模拟 7–14 个“天”，每天 10–20 轮，共 100–200 轮。每个 episode 包含中性任务、人格相关任务、错误纠正、角色冲突、记忆污染和系统提示扰动。时间可以在离线运行，不需要真实等待。

建议先做 50 个 episode 的 pilot，再扩展到 200 个 episode。每个条件使用同一任务日程和随机种子，确保方法间是配对比较。

### 4.3 比较的持久化机制

1. **Prompt-only：** 每轮附加人格 profile；
2. **Profile memory：** 从历史中检索人格承诺和用户偏好；
3. **Activation steering：** 每轮注入人格方向；
4. **Parameter-internalized：** 使用方案一或方案三训练后的策略；
5. **No-memory control：** 不保留历史，只保留当前任务。

### 4.4 动态状态和指标

对每一轮输出计算人格行为向量 $p_t$，并将情境期望状态记为 $q_t$。分解为：

- **Trait signal：** 在不同情境平均后仍然稳定的目标差异；
- **State adaptation：** 情境变化时合理的短期响应；
- **Drift：** 无情境原因的长期偏移。

主要指标：

$$\text{Drift}=\frac{1}{T}\sum_t\|p_t-p_0\|,$$

- 跨天 ICC；
- 长程人格矛盾率；
- 目标冲突后的恢复轮数；
- 记忆污染率和错误记忆纠正率；
- 状态适应误差（应变时是否仍机械保持同一风格）；
- 长程 sycophancy、隐私和安全失败率；
- token 成本、延迟和上下文长度。

### 4.5 必做实验

**A. 稳定性曲线。** 在 7、14 天分别计算 ICC、drift 和 contradiction；不要只报告最终一天。

**B. 记忆消融。** 比较完整记忆、无记忆、随机删除 30% 记忆、注入一条错误人格记忆；测人格恢复和记忆纠正。

**C. 冲突恢复。** 在中段插入与目标人格冲突的系统/用户提示，记录恢复时间和安全失败；测试方法是否在冲突后永久漂移。

**D. 主题迁移。** 训练/初始会话使用工作主题，测试迁移到教育、健康、社交和创作主题。

**E. 模型/策略更新。** 在 episode 中途更换 system prompt 或检索库版本，测量 persona drift 和 capability regression。

### 4.6 基线和消融

基线：prompt-only、profile memory、activation steering、方案一策略。消融记忆长度、检索 top-k、状态摘要器、冲突恢复模块和上下文窗口。

### 4.7 支持顶会结论的最低结果

- 训练后的策略在至少 7 天自动 episode 中保持更高 ICC、更低 contradiction 和可接受 drift；
- 不是通过拒绝所有变化实现稳定，而是在应变情境中保持合理 state adaptation；
- 记忆污染和冲突后能够恢复，不出现永久人格劫持；
- 长程安全和 sycophancy 不劣于短程评测；
- 结果在第二模型家族或不同用户模拟器上仍成立。

若长期指标完全依赖同一个用户模拟器，必须换第二个模拟器和脚本；否则只能说明“适应了模拟器”。

### 4.8 资源估计

50–200 个 episode、每个 100–200 轮会产生约 5,000–40,000 次推理调用。使用小型本地用户模拟器和缓存可控制成本；主要瓶颈是评测调用，不是训练。该方案适合作为方案一的第二阶段，而不建议在没有稳定单轮方法时单独开做。

## 6. 资源受限的两周 pilot

### 第 1–2 天：管线验收

完成 100 个模板、300 个自动扩写情境、一个 judge rubric 和全部指标脚本。用 base model 运行，确认规则分、judge 分和一致性指标不会全部饱和或全部为零。

### 第 3–5 天：基线

训练 prompt-only、LoRA/SFT 和普通 DPO 的小版本。只用 500–1,000 个训练情境，在 200 个模板外测试情境上跑完整自动评测。若 baseline 之间没有可测差异，先修复任务定义，不要扩大模型。

### 第 6–9 天：方法试验

选择方案一或方案三实现最小版本；方案二只做 2–3 个 trait 的干预矩阵；方案四只做 20 个 7 天 episode。记录训练、评测和 judge 成本。

### 第 10–12 天：攻击与泄漏检查

加入 trait 词屏蔽、提示改写、错误事实、越权请求和第二 judge。若主方法只在原始 rubric judge 上提升，而在词屏蔽/第二 judge 上消失，判定为评测器过拟合。

### 第 13–14 天：选择主线

选择满足以下条件的路线：

- 未见情境有稳定正增益；
- 隐藏行为效度与表面人格分数同方向；
- 安全/真实性没有明显回归；
- 评测结果对第二 judge 和提示改写不敏感；
- 单次实验成本可扩展到 3 seeds。

若四条路线均不满足，不应继续堆算力；优先重写人格行为定义和情境集。

## 7. 选择建议

### 选择方案一，如果

你希望在有限人手下得到最稳妥的主论文。它的主要贡献是心理测量约束奖励和隐藏行为效度，训练与已有 DPO 基础兼容。

### 选择方案二，如果

团队能承担较多反事实数据和严格因果分析，且愿意接受较高失败概率。它的顶会潜力最高，但不能只依赖人格雷达图。

### 选择方案三，如果

团队擅长安全对齐、约束优化和多目标实验。它最容易形成清晰的 trade-off 图和实际部署叙事。

### 选择方案四，如果

已经有稳定的单轮方法，并且希望把贡献扩展到长期代理。不要把它作为第一步；长程评测会放大数据和模拟器缺陷。

## 8. 推荐主论文结构

在当前“缺少人手”的约束下，推荐以下顺序：

1. **主线：方案一。** 先证明心理测量约束能提高未见情境行为效度和跨提示稳定性。
2. **安全扩展：方案三。** 加入真实性、安全性和 sycophancy 约束，展示 Pareto 前沿。
3. **长期扩展：方案四。** 只在前两者成立后做 7 天自动 episode。
4. **独立高风险线：方案二。** 若 pilot 显示干预矩阵具有明显对角结构，再投入完整因果解耦论文。

最小顶会论文应回答三个问题：

1. 人格分数提升是否能够预测隐藏行为？
2. 这种行为改变能否跨提示、跨情境和跨模型保持？
3. 人格目标是否以真实性、安全性和能力为代价？

如果不能同时回答，论文应缩小主张，不要宣称“模型拥有了人格”。
